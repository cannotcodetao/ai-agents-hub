第 1 组 · SSH 加固（低风险练手，改完立刻验证）

这 3 项都是改 SSH 配置文件 + 重启服务，操作模式相同。做完一组就有手感了。

09
SSH 空闲超时 = 0（应设为 600-900 秒）
中危
左侧菜单 → 终端 → 打开命令行界面

这是什么？SSH 默认不会自动断开空闲连接。如果有人拿到了你的 SSH 会话（比如你忘关终端），他们可以一直用下去。

操作步骤

  1. 点左侧 「终端」，进入命令行界面
  2. 输入以下命令打开 SSH 配置文件： 
    复制整行nano /etc/ssh/sshd_config
  3. 在文件里找到 ClientAliveInterval 这一行（可能被 # 注释掉了）
    📸
    截图 09-A · sshd_config 文件内容
    截取 nano 编辑器里 sshd_config 的内容，展示 ClientAliveInterval 所在行附近
  4. 把这一行改成（或新增一行）： 
    ClientAliveInterval 600
  5. 保存退出：Ctrl+O 回车确认 → Ctrl+X 退出
  6. 重启 SSH 服务使配置生效： 
    systemctl restart sshd
  7. ⚠️ 不要关闭当前终端！新开一个终端窗口，尝试 SSH 登录服务器，确认能连上再继续
新终端能正常 SSH 登录 → 且闲置约 10 分钟后会自动断开（说明生效了）
10
未启用 SSH 登录超时（LoginGraceTime）
中危
左侧菜单 → 终端 → 命令行

这是什么？LoginGraceTime 控制用户必须在多少秒内完成登录认证。默认无限制，暴力破解程序可以慢慢试密码。

操作步骤

  1. 在终端输入： 
    nano /etc/ssh/sshd_config
  2. 找到或添加 LoginGraceTime，设为： 
    LoginGraceTime 60
  3. Ctrl+O 保存 → Ctrl+X 退出
  4. 重启： 
    systemctl restart sshd
  5. 同 #09，新终端验证可登录
新终端 SSH 登录正常 → 如果 60 秒内不输密码就会断开
13
SSH 未明确使用 Protocol 2
中危
左侧菜单 → 终端 → 命令行

这是什么？SSH Protocol 1 已过时且有已知漏洞。现代 OpenSSH 默认只用 Protocol 2，但配置文件里没写明的话扫描器会报。

操作步骤

  1. 终端输入： 
    nano /etc/ssh/sshd_config
  2. 在文件任意位置添加一行： 
    Protocol 2
  3. 保存退出 → 重启： 
    systemctl restart sshd
现代 Linux 的 OpenSSH 通常已默认只支持 Protocol 2。这步主要是让扫描器不报错，实际安全增益有限。
重新跑一次宝塔安全扫描，#13 应消失或降级

第 2 组 · 面板端口 + 系统防火墙（⚠️ 高危，仔细看警示）

04
面板端口为默认 8888
中危
左侧菜单 → 设置 (右上角) → 面板设置

这是什么？宝塔默认用 8888 端口，全网都知道。攻击者可以针对这个端口扫 + 暴力破解。

操作步骤

  1. 点宝塔面板右上角的齿轮图标 ⚙️「设置」
  2. 找到「面板端口」输入框，当前值是 8888
    📸
    截图 04-A · 面板设置页面
    截取「设置」页面，展示「面板端口」输入框所在位置（通常在顶部区域）
  3. 改成高位自定义端口，例如 28888（范围建议 10000-65535）
  4. 点「保存」
  5. 重要：如果你的云服务器有安全组（腾讯云/阿里云等），去云控制台的安全组规则里，先放行新端口 28888，再考虑是否删除 8888
  6. 保存后宝塔会提示用新端口访问，记下新端口号
改完后旧端口立即失效！如果安全组没放行新端口，你会无法访问面板。建议：先加安全组规则 → 改端口 → 测试新端口能访问 → 再删旧端口规则。
浏览器访问 http://124.221.166.181:28888/xxxx（xxxx 是你的安全入口）能正常打开面板

14
sudoers 存在 NOPASSWD 标记
高危
左侧菜单 → 终端 → 命令行

这是什么？NOPASSWD 意味着某些用户可以用 sudo 执行任何命令而不需要输入密码。如果攻击者拿到这个用户的 shell，就直接获得 root 权限。

操作步骤

  1. 先确认你有 root 密码或其他 sudo 用户！这一步改错可能导致无法提权。
  2. 终端输入，查看当前的 sudoers 内容： 
    cat /etc/sudoers
  3. 找有没有包含 NOPASSWD 的行，类似： 
    root    ALL=(ALL)    NOPASSWD: ALL
    📸
    截图 14-A · sudoers 文件内容（cat 输出）
    截取终端里 cat /etc/sudoers 的输出，高亮含 NOPASSWD 的行
  4. 同样检查 cloud-init 用户： 
    cat /etc/sudoers.d/90-cloud-init-users
  5. 备份原文件： 
    cp /etc/sudoers /etc/sudoers.bak
cp /etc/sudoers.d/90-cloud-init-users /etc/sudoers.d/90-cloud-init-users.bak
  6. 用 visudo 安全编辑（比直接 nano 更安全，有语法检查）： 
    visudo
  7. 找到含 NOPASSWD 的行，在行首加 # 注释掉，或者删掉 NOPWD:ALL 部分
  8. 同样处理 /etc/sudoers.d/90-cloud-init-users： 
    visudo -f /etc/sudoers.d/90-cloud-init-users
  9. 保存后 visudo 会自动检查语法；如果有错会提示你修复
  10. 验证：执行 sudo whoami，应该要求输入密码而不是直接返回 root
90-cloud-init-users 是云厂商（腾讯云）初始化实例时创建的。如果删掉 NOPASSWD 后发现某些自动化脚本需要免密 sudo，可以从备份恢复。
最安全的做法：保留 NOPASSWD 但限定为特定命令（如 NOPASSWD: /usr/bin/systemctl restart nginx），而非 ALL。
sudo whoami 要求输入密码；sudo -l 不再显示 (NOPASSWD)

第 3 组 · 特权文件 + 密码策略加固

01
存在 SUID/SGID 特权文件
中危
左侧菜单 → 终端 → 命令行

这是什么？SUID/SGID 是 Linux 特殊权限位，允许普通用户以文件所有者/组的身份执行程序。攻击者利用这些文件可以进行权限提升。

操作步骤

  1. 终端依次执行以下命令（去除 SUID）： 
    chmod u-s /usr/bin/chage
chmod u-s /usr/bin/gpasswd
chmod u-s /usr/bin/chfn
chmod u-s /usr/bin/chsh
chmod u-s /usr/bin/newgrp
chmod u-s /bin/mount
chmod u-s /bin/umount
  2. 去除 SGID： 
    chmod g-s /usr/bin/write
移除 SUID 后，普通用户将无法使用 mount/umount 等命令。确保你通过 root 或 sudo 操作服务器即可，不受影响。
执行 find / -perm -4000 -o -perm -2000 后上述文件不再出现在结果中
06
未限制密码重复使用次数
中危
左侧菜单 → 终端 → 命令行

操作步骤

  1. 备份： 
    cp -p /etc/pam.d/system-auth /etc/pam.d/system-auth.bak
  2. 编辑： 
    nano /etc/pam.d/system-auth
  3. 找到含有 password sufficient 的行，在末尾追加 remember=3
    例如改成： 
    password sufficient pam_unix.so sha512 shadow nullok try_first_pass use_authtok remember=3
    📸
    截图 06-A · system-auth 文件中 password sufficient 行
    截取 nano 里 system-auth 文件，高亮 password sufficient 那一行（修改前后各一张更好）
  4. Ctrl+O 保存 → Ctrl+X 退出
改密码时，如果新密码和最近 3 次用过的相同，系统会拒绝
11
密码复杂度未设 minclass
中危
左侧菜单 → 终端 → 命令行

操作步骤

  1. 编辑密码质量配置： 
    nano /etc/security/pwquality.conf
  2. 找到或添加 minclass 行： 
    minclass = 3
  3. 含义：密码至少包含 3 类字符（小写字母 / 大写字母 / 数字 / 特殊符号 中选 3 类）
  4. 保存退出
下次改密码时，如果密码只包含一类或两类字符（如纯数字），会被拒绝
12
密码修改间隔 PASS_MIN_DAYS < 7
中危
左侧菜单 → 终端 → 命令行

操作步骤

  1. 编辑登录定义： 
    nano /etc/login.defs
  2. 找到 PASS_MIN_DAYS，改为： 
    PASS_MIN_DAYS 7
  3. 对已有 root 账号也生效： 
    chage --mindays 7 root
  4. 保存退出
执行 chage -l root 查看，Minimum number of days between password change 应为 7

第 4 组 · 服务清理（MySQL / PHP / telnet）

这组需要你判断：这些服务是否真的在被使用？纯静态站理论上不需要。

03
MySQL 端口 3306 对外开放
中危
左侧菜单 → 安全 → 系统防火墙 / 端口规则

这是什么？MySQL 数据库默认监听 3306 端口且允许任意 IP 连接。攻击者可以暴力猜密码。

先判断：你是否在用 MySQL？

  1. 终端执行： 
    systemctl status mysqld
    📸
    截图 03-A · MySQL 服务状态
    截取 systemctl status mysqld 的输出，看 active (running) 还是 inactive/dead

方案 A：不用 MySQL → 关闭 + 删除防火墙规则

  1. 停止并禁用 MySQL： 
    systemctl stop mysqld
systemctl disable mysqld
  2. 去「安全 → 系统防火墙 → 端口规则」，删除 3306 的放行规则

方案 B：在用 MySQL → 限定 IP 访问

  1. 在防火墙端口规则里，把 3306 从「所有 IP」改为仅允许特定 IP（如你的本地出口 IP 或 127.0.0.1）
  2. 或在 MySQL 配置里绑定地址： 
    nano /etc/my.cnf
    在 [mysqld] 下加 bind-address=127.0.0.1
你的站点是纯静态（Nginx 直出 HTML），大概率不需要 MySQL。如果只是宝塔安装时顺带装上的，建议直接关掉（方案 A）。
外部扫描 3306 端口不通；或 netstat -tlnp | grep 3306 显示绑定在 127.0.0.1

  2. 切换到 「已安装」标签

17
未配置命令行超时退出（TMOUT）
低危
左侧菜单 → 终端 → 命令行

操作步骤

  1. 编辑全局 profile： 
    nano /etc/profile
  2. 在文件末尾追加一行： 
    export TMOUT=300
  3. 使配置立即生效： 
    source /etc/profile

含义：命令行空闲超过 300 秒（5 分钟）自动退出。等保要求 ≤ 600 秒。

19
未开启 TCP SYN Cookie 保护
低危
左侧菜单 → 终端 → 命令行

操作步骤

  1. 编辑内核参数： 
    nano /etc/sysctl.conf
  2. 在文件末尾追加： 
    net.ipv4.tcp_syncookies = 1
  3. 使参数立即生效： 
    sysctl -p

含义：启用 SYN Cookie 可缓解 SYN Flood 类 DDoS 攻击。现代内核大多默认已开启，这步主要是确保配置持久化。

执行 sysctl net.ipv4.tcp_syncookies 返回 net.ipv4.tcp_syncookies = 1
18
未禁用 wheel 组外用户 su 为 root
低危
左侧菜单 → 终端 → 命令行

操作步骤

  1. 先确认自己在 wheel 组里： 
    groups
    看输出是否包含 wheel
  2. 如果不包含，把自己加入： 
    usermod -aG wheel $(whoami)
  3. 编辑 PAM su 配置： 
    nano /etc/pam.d/su
  4. 在文件中添加一行（通常放在 auth 相关行的附近）： 
    auth required pam_wheel.so
  5. 保存退出
启用后，只有 wheel 组的用户才能 su 到 root。如果你不在 wheel 组里又没其他 root 途径，就会锁死。务必先执行步骤 1 确认自己在 wheel 组。
用非 wheel 组用户执行 su - 应被拒绝；wheel 组用户可以正常 su
15
未安装 TCP Wrappers
低危
左侧菜单 → 终端 → 命令行

操作步骤

  1. OpenCloudOS/CentOS 系执行： 
    yum install tcp_wrappers -y

TCP Wrappers 是较老的访问控制工具，现代系统多已弃用（由 firewalld/iptables 替代）。装上可以让扫描器不报错，实际防护意义有限。可跳过。
