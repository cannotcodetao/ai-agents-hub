## § B · 搜索栏 UX 问题：输入 "video" 后看不到结果

### 根因分析（已看代码确认）

**问题表象**：

- 用户在左侧固定 Sidebar 的搜索框输入 `video`
- `App.tsx` 第 100~124 行 `filteredAgents` 确实按 `searchQuery` 过滤了 221 个项目
- 但结果在页面**很靠后**的位置才渲染，需要从 Hero 区域向下滚动
- 用户停留在 Hero 区域时感觉「搜索没反应」

**页面渲染顺序**（截图对应）：

```
Sidebar(固定, lg:pl-[300px])
└── 主内容
    1.  备案横条              ← 首页顶部
    2.  <Hero/>              ← 首页首屏（标题 + 开始探索）
    3.  <CategoryGrid/>       ← 分类浏览卡片（与搜索无关）
    4.  <TrendingGitHub/>     ← GitHub 趋势热点（与搜索无关）
    5.  <Trending/>           ← 项目趋势榜（与搜索无关）
    6.  <section id="explore"> ← 🔍 「完整项目列表」(受搜索影响)
```

`<section id="explore">` 才是真正显示 `filteredAgents` 的地方，它**位于第 5 个区块之后**。从 Hero 滚到 `#explore`，需要跨过 4 个独立区块，体感「搜索没反应」非常正常。

**核心症结**：在搜索场景下，Hero / CategoryGrid / Trending / TrendingGitHub **四块内容都是噪声**——用户搜「video」只想看匹配项目，不想看精选/趋势，但它们还在那里抢走首屏位置。

### 候选解决方案（请挑一个 / 组合）

#### 方案 B-1 · 搜索时自动滚动到 `#explore`（最小改动，推荐）

- 监听 `searchQuery` 变化，有值时 `scrollIntoView('#explore')` 自动跳转
- 优点：改动最少（~10 行），天然兼容现有交互
- 缺点：第一次输入就强制滚动，用户可能错过搜索中的输入体验
- 可选：滚动后保留搜索栏在视口（Sidebar 已 fixed，没问题）

#### 方案 B-2 · 搜索时折叠 Hero/Trending/CategoryGrid，聚焦结果

- `searchQuery` 非空时，把 Hero / CategoryGrid / TrendingGitHub / Trending 全部 `hidden`
- 仅显示「找到 X 个项目」+ grid 结果
- 优点：体验最干净，搜索即「结果模式」
- 缺点：改动较大（涉及 `view==='home'` 内的条件分支，10+ 行 JSX）

#### 方案 B-3 · 在 Hero 上方插入「搜索结果预览」（增强体验）

- Hero 区域下方加一个"找到 N 个项目"小条 + 紧凑前 3 条预览（卡片可点开）
- 用户感受"立刻看到"，不用等滚下去
- 优点：不丢 Hero 也不强制滚动
- 缺点：多一块 DOM（首屏变厚），预览与下方 grid 略有重复

#### 方案 B-4 · Sidebar 内置「实时下拉结果」

- 在 Sidebar 搜索框下方加一个 5~10 条的下拉列表，显示匹配的 name + stars
- 用户感受最强：搜索 = 立刻看到候选
- 缺点：需要新增 Sidebar 内 list + 滚动锚点，复杂度最高

> **当前推荐**：**B-2（B 折叠模式）** 或 **B-2 + B-1（先折叠 + 自动滚动）**。
>
> 理由：与现有「点侧边栏分类 → 滚动到 explore」逻辑最一致；搜索时切到「结果模式」是最清晰的视觉信号；改动可控（20~30 行）。

> **决策要你拍**：
> 1. 是否走 B-2（折叠）？还是最小改动 B-1？
> 2. B-2 里，搜索时 Hero 是否完全收起？还是只缩成一行 banner "正在搜索 xxx"？
